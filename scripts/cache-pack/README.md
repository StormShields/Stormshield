# Building and publishing a Region's Cache Pack

Run once per Region, ahead of the event, with internet. Spec: `docs/specs/regions-events-and-sandbox.md` decision 2, layout: `docs/specs/wire-formats.md`.

```
scripts/build-cache-pack.sh nepal       # reads regions/nepal/region.json, writes node/build/nepal/cache-pack.zip
gh release create cache-pack-nepal-v1 node/build/nepal/cache-pack.zip   # tag: cache-pack-<region>-v<N>
```

The Release asset must be named `cache-pack.zip`. Then put the new number in `RELEASED_PACKS` (`node/src/storm_shield/cache_pack.py`): a Node with no `CACHE_PACK_URL` downloads its Region's pack (`NODE_REGION`) from `cache-pack-<region>-v<N>`, and the Sandbox does the same when `node/build/<region>/cache-pack.zip` is not on disk. A Node never re-downloads a valid pack, so a new version reaches a Node only when its `CACHE_PACK_DIR` is empty. `CACHE_PACK_URL` still overrides the source; Sensor Nodes set it to the Hub's `/api/cache-pack.zip` and take their Region from the `region.json` inside the pack.

- `--output <file>` and `--work-dir <folder>` (default `build`, where the OpenStreetMap extract is kept between builds) are the only options. The build needs `uv`; `pyrosm` (the Road graph) is fetched by the script for that run only and is never a Node dependency.
- **Everything comes from the Region file.** Its `bbox` is the box for the basemap, terrain, Routes and Weather Grid; its `shelters` and `high_ground` become `shelters.json` and `high_ground.json`; its `water` files become `river.geojson` and `flood_prone.geojson`; the Events in `regions/<name>/events/` become `events/<id>.json`. The build checks the Region file and every Event file against their schemas first and names the bad field and the file; an Event's Official Alerts must come from sources the Region lists. A made-up Event (`"real": false`) is packed as written, its keyframes being its weather, and the build fetches no archive weather for it.
- **Sources** (`sources` in the Region file, each with a `url` and the `credit` the map prints): `terrain` is a Terrarium tile address with `{z}/{x}/{y}`; `roads` an OpenStreetMap extract (`.pbf`, downloaded to the work folder when it is an address); `basemap` an Overpass API endpoint; `weather` Open-Meteo's archive endpoint. A source that is not an address is a file path under the Region's folder, which is how the tests build a pack from local files. When a source fails, the build stops and says which one and the status (never the address, which can carry a key).
- **Basemap** (`basemap/*.geojson`): one Overpass query for the bbox returns lakes and riverbanks, rivers, canals and named streams, the coastline, roads from motorway to residential, and named places. Names are kept only in Latin letters (the map has no Devanagari font). Water polygons come from closed ways and from multipolygon relations whose outer ways join into rings; an island in a lake is not cut out, and open sea has no polygon (the coastline is a line; land is the ground). Lines are simplified to about 11 m and rounded to 4 decimals.
- **Terrain** (`elevation/{z}/{x}/{y}.png`): Terrarium tiles at zoom 9 to 12 over the bbox, at most 10 MB. Heights are approximate (the manifest says so) and the map and anything that quotes a height must say "about". The High-ground points read their climb from these tiles.
- **Weather Grid** (`weather_replay.json`): Open-Meteo's archive asked once, at the grid points that cover the bbox, for the UTC days from the day before the earliest Event to the day after the latest. A Region with no Event gets none.
- **Road graph and Routes** (`roads.json`, `routes/`): the shortest drive from each Grid point to each Shelter over the OpenStreetMap extract clipped to the bbox, left out when it crosses the Flood-Prone Area. The grid starts at 100 m and coarsens to 250 and 500 m until the Routes fit 5 MB compressed.
- **Shelters** are the `shelters` of the Region file; each entry's `source` note is for reviewers and is left out of the pack. The Region file already refuses a Shelter outside the bbox.
- **High-ground points** carry their own `town` and `town_pos` (the town's centre, where the walk starts) in the Region file. The build fails on a point inside or within 100 m of the Flood-Prone Area, a climb under 50 m, or a town more than 2 km away. Nepal's points are PLACEHOLDERS picked from the tiles, not visited.
- `regions/nepal/sources/river.geojson` (the river line with River km and a speed per reach) and `flood_corridor.geojson` there (the Flood-Prone Area: 150 m each side of the river line, approximate) are written by `uv run --project node python scripts/derive_river.py` from OpenStreetMap ways through Overpass. Run it again only when the river inputs change, and commit the two files. The speeds are reconstructed from reported arrival times, and each reach cites its source. River km is zero at the Lhende-Kyirong confluence (28.2781 N, 85.3770 E), negative upstream.
- `bbox` in the manifest is `[south, west, north, east]`.
- Nepal's country border, district layers and whole-of-Nepal Weather Grid, which an earlier build (`pack_nepal.py`) made, are gone, and so are the CARTO raster tiles. The map reads the generic basemap instead.
- **A coast Region's Flood-Prone Area is traced from the terrain** (`pack_flood_prone.py`): the zoom-12 tiles are read on a grid of about 30 m cells, the cells above sea level and below `flood_prone_below` are joined into polygons with holes, rings under about 1.5 ha are dropped and outlines are straightened to within a cell. Sea is anything at 0 m or lower, so marsh and canals the terrain puts above 0 are traced with the land. The file's feature says `approximate`, and the map captions it so. A river Region reads its corridor file instead.
- **Every Shelter must lie outside the Flood-Prone Area**, of either kind; the build fails naming the ones inside. A coast has no river line, so it writes no `river.geojson`, and its Region may list no High-ground points (they measure their climb above the river).
